Email environment

How THERESE reads outbound mail settings from .env

Where settings live

  • Secrets belong in the file .env in the project root (same folder as manage.py). That file is gitignored and must not be pushed to GitHub.
  • The generic template is .env.example. It is versioned. Copy it to .env on a new server, then fill in real values: python create_env_template.py
  • After changing .env, restart the application so Django reloads the values.

Passwörter nur in der lokalen .env, niemals im Repository.

Trigger email templates

Popup text and email body are independent. Triggers themselves are created under Login Popup Settings. Emails are sent when the event happens (new task, status change, comment, checklist, chemical item, contract saved in the X-months window). Popups still appear at the next login. First login and “login after date/time” emails are sent at login. Time-window contract reminders that nobody edited can be sent daily with python manage.py send_due_trigger_emails. Click a variable chip to insert it into the HTML body. Values are replaced when the email is sent. Versand beim Ereignis, nicht erst beim nächsten Login. Empfänger: berufliche E-Mail, sonst Benutzer-E-Mail.

Template variables

Only variables that match the trigger have values at send time. Others stay empty. List variables insert every matching record the recipient may see (items they archived are omitted). Status-specific lists also work as {% verbatim %}{{ purchase_orders:not_yet_processed }}{% endverbatim %} or {% verbatim %}{{ assigned_tasks:in_progress }}{% endverbatim %}.
